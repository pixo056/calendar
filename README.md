# Студенческий календарь — ТОП-105Б и другие группы УУНиТ

Отдельное учебное web-приложение `calendar`. Исходный проект `JavaProject` не изменялся. Календарь месяца, список событий, поиск, фильтр по типу, создание, редактирование и удаление с подтверждением. Добавлен выбор из 3065 групп со страницы расписания УУНиТ; группа по умолчанию — ТОП-105Б. На телефоне открывается удобный список событий.

Типы: контрольная, зачёт, экзамен, мероприятие, дедлайн. Введённые пользователем события хранятся в H2 на диске и сохраняются между запусками. Тестовые события не добавляются в рабочую базу. Автоматический импорт занятий из университетского расписания не выполняется.

Подробно: [данные и устройство базы](docs/DATABASE.md), [запуск на Android/iOS через Wi-Fi](docs/PHONE.md).

## Что нужно для разработки

| Компонент | Выбор и состояние |
| --- | --- |
| IDE | Установленная IntelliJ IDEA 2026.2.1 |
| JDK | Microsoft OpenJDK 25.0.4.1 LTS, уже установлен: `%USERPROFILE%\.jdks\ms-25.0.4.1` |
| Сборка | Maven Wrapper в проекте, Maven 3.10.0; отдельная установка Maven не нужна |
| Сервер | Spring Boot 4.1.1, Spring MVC, встроенный Tomcat |
| Работа с данными | Spring Data JPA, Hibernate, H2 в файловом режиме |
| Проверка ввода | Jakarta Validation |
| Интерфейс | HTML, CSS, JavaScript, русская локализация, адаптивная разметка |
| Проверки | JUnit, Spring Boot Test и HTTP-проверки API |

Для этой версии не нужны Node.js, npm, Docker, отдельный Tomcat, PostgreSQL или платные плагины IntelliJ. Приложение запускается как обычный Java main-класс. Встроенных Java и Maven возможностей IDE достаточно; поддержка Spring в редакторе необязательна.

Зависимости скачиваются из Maven Central в `.mvn/repository`, Maven Wrapper — в `.mvn/user-home` при использовании `start.cmd`/`test.cmd`. Они изолированы от других проектов. Эти каталоги не следует добавлять в Git или в архив исходников.

В `.mvn/settings.xml` все обращения Maven направлены в официальный Maven Central; таймауты подключения и ответа ограничены в `.mvn/maven.config`. В `.idea/misc.xml` заранее указан зарегистрированный в этой IDE SDK `ms-25`, а в `.idea/encodings.xml` — UTF-8. Эти файлы относятся только к новому проекту.

## Открыть в IntelliJ, сохранив старое окно

1. **File → Open** → выбрать эту папку `calendar` или её `pom.xml`.
2. Если IDE спросит формат — **Open as Project / Maven**.
3. В выборе окна нажать **New Window**. Не выбирать **This Window** или **Attach**.
4. Дождаться импорта Maven. Если он не начался: правой кнопкой на `pom.xml` → **Add as Maven Project**, затем **Reload All Maven Projects** в панели Maven.
5. В **File → Project Structure → Project**: SDK **ms-25**, language level **25** или **SDK default**. Если SDK отсутствует, **Add SDK → JDK** и указать `%USERPROFILE%\.jdks\ms-25.0.4.1`.
6. В **Settings → Build, Execution, Deployment → Build Tools → Maven**: Maven home — **Use Maven wrapper**. В **Importing** и **Runner** выбрать **Project JDK**.
7. В **Settings → Editor → File Encodings** убедиться, что Project Encoding — **UTF-8**. Файлы проекта уже записаны в UTF-8; настройки других проектов менять не требуется.

Подготовлена общая конфигурация запуска `.run/Calendar.run.xml` с именем **Calendar**. Если после импорта она не появилась, открыть `src/main/java/ru/top105/calendar/CalendarApplication.java` и нажать зелёный треугольник рядом с `main`. Рабочая папка запуска должна быть корнем `calendar`.

## Запуск

Самый простой способ вне IDE — двойной щелчок по `start.cmd`. Скрипт использует установленный JDK 25, не меняет системный PATH и запускает сервер. Первый запуск может потребовать доступ к Maven Central.

В IntelliJ запустить конфигурацию **Calendar** или `CalendarApplication.main`. После строки `Started CalendarApplication` открыть <http://localhost:8080>.

Остановка: красный квадрат в IntelliJ или Ctrl+C в окне запуска. Не запускайте одновременно две копии с одной базой и портом.

Для PowerShell из корня проекта:

```powershell
$env:JAVA_HOME = "$env:USERPROFILE\.jdks\ms-25.0.4.1"
$env:MAVEN_USER_HOME = "$PWD\.mvn\user-home"
.\mvnw.cmd spring-boot:run
```

Если порт занят, задать переменную `PORT=8081` в конфигурации запуска IDE или `$env:PORT='8081'` перед командой. Адрес будет <http://localhost:8081>.

## Данные и ограничения первой версии

Файл базы: `data/calendar.mv.db` относительно рабочей папки. Для резервной копии остановите сервер и скопируйте папку `data`. Тесты используют отдельные базы в памяти и не меняют пользовательские события.

Обычный запуск слушает `127.0.0.1`. Для телефона в общей сети используйте **Calendar (phone)** в IntelliJ или `start-phone.cmd`: этот режим задаёт `SERVER_ADDRESS=0.0.0.0`. На телефоне нужен IP компьютера, например `http://192.168.1.100:8080`, а не localhost. Подробности и ограничения — в `docs/PHONE.md`.

Авторизации, ролей и уведомлений пока нет. Любой пользователь с доступом к серверу может выбрать группу и редактировать её события. Время события хранится как местное время группы без конвертации часовых поясов.

Схема существующей H2 не изменялась. Принадлежность ID другим группам хранится в отдельном `data/event-groups.properties`; ID без записи относятся к ТОП-105Б. Сохраняйте всю папку `data` вместе. Названия групп лежат в `src/main/resources/catalog/groups.txt`; последнее выбранное название запоминается в браузере. Подробности — в `docs/DATABASE.md`.

Поиск и фильтр действуют на выбранный месяц. Счётчики показывают все события месяца и ближайших семи дней независимо от фильтров. Боковая панель показывает до шести ближайших событий в пределах семи дней. При сохранении события календарь переходит к его месяцу и сбрасывает фильтры, чтобы запись была видна.

## Проверки и сборка

`test.cmd` либо `./mvnw.cmd test` — тесты. `./mvnw.cmd package` — сборка запускаемого JAR в `target/calendar-0.0.1-SNAPSHOT.jar`.

Тесты проверяют запуск контекста, загрузку страницы и ресурсов, создание/получение/изменение/удаление событий, ответы 400/404, все пять типов и необязательное время. Результаты выполненной проверки записаны в `CHECKS.md`.

## API

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/api/groups` | Справочник групп, источник и дата снимка |
| GET | `/api/events` | События по дате и времени |
| POST | `/api/events` | Создать, HTTP 201 |
| PUT | `/api/events/{id}` | Изменить, HTTP 200 |
| DELETE | `/api/events/{id}` | Удалить, HTTP 204 |

Все методы `/api/events` принимают параметр `?group=НАЗВАНИЕ` (значение кодируется как URL). Без параметра используется ТОП-105Б. Чтение и изменение ограничены выбранной группой; обращение к событию другой группы возвращает 404, неизвестная группа — 400. Это разделение данных, а не проверка личности пользователя.

Пример тела POST/PUT (учебный пример, не реальное событие группы):

```json
{"title":"Контрольная по массивам","subject":"Программирование","type":"TEST","date":"2026-10-20","time":"10:30","location":"Аудитория 101","description":"Повторить циклы и массивы"}
```

`type`: `TEST`, `CREDIT`, `EXAM`, `ACTIVITY`, `DEADLINE`. Обязательны название, предмет, тип и дата. Допустимые годы — 1900–9999. `time` можно передать как `null`. Ошибки ввода возвращают HTTP 400, отсутствующее событие — 404.
