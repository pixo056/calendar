# Как работают данные календаря

## Что уже хранится в H2

`data/calendar.mv.db` — файл встроенной реляционной базы H2. Она работает внутри Java-приложения: отдельный сервер базы устанавливать не требуется. Приложение подключается к ней по адресу `jdbc:h2:file:./data/calendar`. Путь отсчитывается от рабочей папки `calendar`.

Основная таблица называется `study_events`. Одна строка — одно событие:

| Поле | Что означает |
| --- | --- |
| `id` | Уникальный номер события, назначается базой |
| `title` | Название, до 120 символов |
| `subject` | Предмет, до 100 символов |
| `type` | Контрольная / зачёт / экзамен / мероприятие / дедлайн |
| `event_date` | Дата |
| `event_time` | Время, может отсутствовать |
| `location` | Аудитория, место или ссылка, до 120 символов |
| `description` | Описание, до 2000 символов |

Это ваши события, введённые через форму. В базе нет учётных записей студентов, паролей, оценок, списков людей, видео или автоматически скачанного расписания. Сам файл содержит также служебные структуры H2: схему таблицы, первичный ключ и сведения для хранения и восстановления записей.

Выбор групп добавлен без изменения исходной сущности `StudyEvent` и схемы `study_events`. Проверки выполняются на отдельных базах в памяти. В Git и выпуск не входит база прежнего владельца: при первом запуске у получателя создаётся чистая база.

## Где теперь указана группа события

Чтобы не менять схему существующей H2, используется дополнительный файл `data/event-groups.properties`. Он создаётся при первом сохранении события для группы, отличной от ТОП-105Б, и содержит пары «ID события → название группы».

Например, `42=ТОП-106Б` означает: событие с ID 42 относится к ТОП-106Б. Все ID без отдельной записи относятся к **ТОП-105Б**. Так прежние события продолжают отображаться в вашей группе без массового изменения строк базы.

Файл записывается в UTF-8 через временный файл и атомарную замену. Если сохранить принадлежность группе не удаётся, создание события откатывается транзакцией H2. При редактировании и удалении сервер проверяет соответствие ID выбранной группе. Перенос событий между группами пока не предусмотрен. Старые ID в файле привязок могут оставаться после удаления события: номера база не переиспользует при обычной работе, поэтому это не создаёт новых событий и не меняет остальные.

Это способ сохранить совместимость с исходной схемой базы. При дальнейшем переходе на полноценную многопользовательскую систему естественно будет хранить группы и связи в таблицах с миграцией. Сейчас такой миграции нет.

## Остальные данные

- `src/main/resources/catalog/groups.txt` — 3065 уникальных названий групп, полученных 14.10.2026 со [страницы расписания УУНиТ](https://isu.uust.ru/class_schedule/). Это справочник в составе приложения, не таблица H2. Для его использования Интернет при каждом запуске не требуется. Автоматическое обновление списка и импорт занятий не реализованы.
- `calendar.selectedGroup` в `localStorage` браузера — только последняя выбранная группа. На телефоне и компьютере выбор запоминается независимо; сами события из `localStorage` не читаются и туда не записываются.
- `.mvn` — Maven и библиотеки проекта, `target` — результаты сборки, `work` — проверочные материалы. Это не ваши события.

## Что происходит при нажатии «Сохранить»

1. Браузер отправляет поля формы и выбранную группу в Java-сервер через `/api/events?group=...`.
2. Сервер проверяет обязательные поля, длины, дату и наличие группы в справочнике.
3. Spring Data JPA / Hibernate сохраняет строку в H2. Для другой группы отдельно сохраняется принадлежность ID.
4. Сервер возвращает сохранённое событие; интерфейс обновляет список, календарь и счётчики.

При открытии календаря сервер читает события из H2 и возвращает только записи выбранной группы. Поиск, фильтр типа и расчёт счётчиков выполняет JavaScript в браузере. При перезапуске события остаются в файле базы.

База лежит в папке приложения на компьютере запуска. При изменениях из другого окна браузера обновите страницу, чтобы получить актуальные записи; автоматического обновления в реальном времени пока нет. Специальный режим сетевого подключения к компьютеру прежнего владельца удалён.

## Резервная копия

Остановите приложение и скопируйте **всю папку `data`**, включая `calendar.mv.db` и `event-groups.properties`, если он уже появился. Восстанавливать нужно эту пару из одной копии. Не удаляйте файл привязок и не переносите его отдельно от базы: без него события других групп будут считаться событиями ТОП-105Б.

Выбор группы — фильтрация календаря, а не авторизация. Сейчас любой, кто имеет сетевой доступ к серверу, может выбрать любую группу и редактировать её события. Пользователи и роли — отдельный следующий этап.
